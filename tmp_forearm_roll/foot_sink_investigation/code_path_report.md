# 脚部下沉：代码路径与隔离实验

正式插件未改。正式 `retarget.py` SHA256 `5d679723197880212ac8ccf8b21ab79fb66afaa299c0d36a4573accad80ac06f`，`bl_info` 版本 1.7.3。实验在无头新场景中运行独立副本 `tmp_forearm_roll/humanoid_retarget`，没有保存 blend。

## 调用链（代码确认）

- `_options_from_settings`（正式 `__init__.py:220`）把 `use_foot_ik`、`foot_floor_enabled`、`foot_floor_alpha`、`foot_floor_height_m` 装进 `RetargetOptions.foot_ik_settings`。
- `_bake_retarget`（正式 `retarget.py:1681`）只在 `use_foot_ik or use_hand_ik` 时创建 `ik_geometry`（1732 行）。脚和手都关时走 `_apply_body_orientations`（1811）加 `_hips_translation`（1822 的 else 分支），然后逐帧写 `rotation_quaternion` 和 `location` 关键帧（1860）。
- 脚 IK 开时，骨盆改走 `_hips_translation_with_floor`（1816），随后 `apply_contact_ik`（1853，非通道路径）或 `_apply_pose_channels`（1832，通道路径）。
- `apply_contact_ik`（正式 `ik.py:37`）对脚链用 `generate_limb_goal` 生成踝目标，再调用 `constrain_goal_floor`（74）和 `plant_goal`，最后 `_solve_chain` 两骨求解并 `_write_end_rotation` 写脚朝向。
- 姿势通道路径在 `_build_pose_channel_goals`（正式 `retarget.py:1340`）里对 `foot_l/foot_r` 同样调用 `constrain_goal_floor`（1379）。

因此地面钳制只作用于 IK 的踝目标点。当前映射没有脚趾，目标是脚骨头部（踝），不是脚掌接触点。`constrain_goal_floor`（正式 `foot_ik.py:218`）按来源踝高度做衰减，`weight = falloff * floor_alpha`，把目标 Z 拉向 `来源踝高 + height_offset * maintain_height_offset`；`height_offset = 目标静止踝高 - 来源静止踝高`（`retarget.py:952`）。它从不看脚趾或网格。

坐标：`build_motion_space`（正式 `motion_space.py:48`）把每个骨架转到 Z 朝上、单位为米、Z=0 在 `floor_height_m` 的空间，对象缩放和旋转在这里吸收一次。FK 的 `_hips_translation`（628）用 `src.matrix_world.to_3x3() @ delta` 再乘根比例，然后用目标 `matrix_world` 逆变换回去。

## 隔离实验（已实测，无头新场景，未保存）

脚本 `run_foot_ik_experiment.py`。A 脚 IK 关，B 脚 IK 开（现有地面约束），C 在 B 之上把踝目标抬到“当前踝到脚趾的下降量”以上（运行时补丁，只在无头进程里）。每组都完整烘焙后在第 0、18、24、52 帧用依赖图求值网格。

A 与正式场景基准逐项吻合：膝角、踝和脚趾高度、网格最低点都相同，证明无头设置与现场是同一个问题。

大腿长保持 0.254 米，小腿关节距从 0.191 米变成 0.153/0.165 米。脚朝向四元数与 A 完全不同，踝到脚趾的 X 分量由正变负，脚趾跑到踝后面。也就是说，打开现有脚 IK 后，烘焙出来的姿态既没有稳定落地（第 18 帧左脚仍穿 0.285 米），又在其他帧把脚抬到 0.3–0.85 米，并且不保持小腿关节距。求解器在烘焙时记录的末端误差多为毫米级，因此问题出在目标生成、骨盆地板路径或求解结果写入关键帧这三层中的至少一层；仅凭烘焙后数据还不能把三者分开，属于尚未验证。

C 与 B 在四帧上逐项相同。把踝目标按脚趾下降量抬高没有改变任何输出，说明脚趾钳制不是当前的主导误差。不要再往这个方向加偏移。

手臂、脊柱和胸的局部四元数在 A、B、C 三组相同（第 24 帧左前臂 `[0.7874, 0.0803, -0.0759, -0.6064]`），脚部求解没有碰上半身。

## 对先前预测的核对

- 只旋转脚掌：未单独跑。踝在第 24 帧左 -0.025 米、右 +0.012 米，脚掌旋转救不了踝高，预测方向成立，但没有实测脚掌旋转后的网格。
- 保持髋高和腿长重解脚部落点：现有 IK 没有做到。髋被抬高 0.018–0.180 米，小腿关节距改变，膝角变化最高 86°。
- 按腿长比例调整髋部下降：第 24 帧需要上移约 0.117 米。B 实际把髋抬高 0.111 米，脚趾反而到了 +0.44/+0.85 米，因为踝目标同时被改写。两者不能直接对照。

## 验收指标（建议，未写入正式插件）

- 脚掌接触参考点取脚部顶点组在依赖图网格中的最低点，不取踝或脚趾骨。接地帧误差目标 ±0.01 米，穿地深度必须为 0（容差 1 毫米）。
- 大腿和小腿关节距相对静止值误差 ≤1 毫米。
- 膝角相对 FK 基准的变化必须逐帧报告；接触帧以外不应出现超过 10° 的无来源变化，膝弯曲方向不得翻转。
- 髋世界高相对 FK 基准变化逐帧报告；根运动为保留位移时，髋的水平位移不得改变。
- 第 0、18、24、52 帧之间脚趾和网格最低点不得出现帧间跳变；整段连续播放另测。
- 脚 IK 关闭时与 A 逐骨一致（四元数差 0°）。
- 烘焙后求值与烘焙时求解器末端误差一致；末端误差 >5 毫米即失败。

## 最小修正方向

不要先改脚趾目标。先在独立副本里把现有脚 IK 的三层分开测：同一帧记录 `generate_limb_goal` 的目标、`_solve_chain` 后的踝位置、写关键帧后重新求值的踝位置。三者对齐后，再决定地面目标该用踝还是脚掌参考点。在这之前，把现有脚 IK 打开交付只会把穿地换成漂浮和脚翻转。
