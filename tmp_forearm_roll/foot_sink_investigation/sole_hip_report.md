# 脚底接地与髋部补偿验证

实验在独立副本 `tmp_forearm_roll\solehip_root\humanoid_retarget` 中进行。正式插件、原始场景、原始动作和已有烘焙没有改动。正式 `ik.py` 哈希仍是 `AD87866E49A40A711A3344C1868CE54A768DA779BA29B355C523E4F7A84A6A08`，`final_bake.blend` 仍是 `624A91AD13DE3E2F770D6DC4750E29183E626BDB265DE92B9AB73FE7E5A68BD5`。工作区的未提交修改保持原样。现场场景仍是第 0 帧、未保存、`filepath=''`。

逐帧数据：`sole_hip_frames.csv`（A、B）和 `sole_hip_c_frames.csv`（修正后的 C）。脚本是 `sole_hip_scan.py` 和 `sole_hip_scan_c.py`，实验开关默认关，只在副本的 `ik.py` 里。

## 第一阶段：缩放污染的来源

结论先说：现场小腿和脚的非单位缩放不是原始骨架的，也不是 `.003` 动作的，是现场会话里没有写入关键帧的姿势状态。它确实污染了骨长、蒙皮和接触判断。

证据有四条。

1. 用全新进程直接导入 `body.FBX`，不做任何重定向，`Bip01` 的骨盆、大腿、小腿、脚、脊柱姿势缩放全是 `(1, 1, 1)`。静止大腿到小腿 0.2542 m、小腿到脚 0.1907 m。
2. 现场目标对象缩放是均匀的 0.01，实验全程保留。现场小腿和脚的姿势缩放却是非均匀的：左小腿 `(0.507, 1.478, 1.376)`、左脚 `(1.914, 0.772, 0.763)`、右小腿 `(0.663, 1.482, 1.030)`、右脚 `(1.311, 0.986, 0.987)`，并且在第 0、12、24、52 帧完全相同。
3. 动作 `Bip01_a050_300000.003` 里有 133 条曲线，小腿和脚只有 `location` 和 `rotation_quaternion`，没有任何 `scale` 曲线。所以切换帧号时这组缩放不会变，它来自姿势本身。
4. 插件的非通道烘焙只给 `rotation_quaternion` 和 `location` 写关键帧；通道烘焙在 `_preserved_pose_scales` 里遇到非统一缩放会直接报错，只写回统一缩放。这组非均匀缩放从插件的烘焙路径里产生不出来。它在现场会话中具体由哪一步引入，现有数据无法确定，不能归给原始骨架、动画通道或重定向过程。

污染的影响是实测的：现场表观小腿段只有约 96–126 mm（静止 190.7 mm），目标网格最低点到 -0.272 m；同一动作在干净进程里最低只有 -0.001 m 量级。

因此实验的归一化不是把缩放强行设成某个猜测值，而是让每个烘焙都从全新导入的状态开始，姿势缩放回到导入时的 1。对象缩放 0.01 没有动。这样得到的骨长（偏差最大 0.039 mm）、静止姿势和世界坐标才可比。

还有一项缺失证据：现场 `hr_settings` 现在显示脚 IK 和手 IK 都是关的，但场景里没有记录 `.003` 烘焙当时的参数，无法确认那份烘焙用了什么设置。实验统一用界面默认等价值：脚 IK 开、地面约束开且强度 1、髋部地面权重 1、膝约束 15°、高度平滑 `height`。

## 第二阶段：三组对照

三组用同一来源、同一目标、同一坐标空间和求解参数，只在副本里切换实验开关。

- A：原始逻辑。
- B：在现有接触复查之后，对判定为接触的脚再做脚底补足。量当前姿势下脚部蒙皮最低点，把踝目标抬到最低点贴地为止，最多再解 3 次。摆动脚不压。
- C：先完整执行 B 并记录每只脚实际用掉的修正量，补偿量取接触脚修正量的较小值，再按到达距离钳制（保持至少 15° 膝屈曲）。先抬骨盆，再用冻结的已修正脚目标重解两条腿。脚目标不重新生成，所以不会被 `pelvis_delta` 抵消，也不会重复抬高。

三组都没有新增低于 -0.01 m 的帧。

| 动作 | 组 | 网格最低 | 严格 Z<0 帧数 | Z<-0.01 m |
| --- | --- | --- | --- | --- |
| `a050_300000` | A | -1.000 mm | 36 | 0 |
| | B | -1.000 mm | 29 | 0 |
| | C | -1.000 mm | 31 | 0 |
| `a050_300010` | A | -2.588 mm | 20 | 0 |
| | B | -2.588 mm | 16 | 0 |
| | C | -2.588 mm | 16 | 0 |
| `a050_301000` | A | -61.042 mm | 10 | 第 0 帧 |
| | B | -61.042 mm | 10 | 第 0 帧 |
| | C | -61.042 mm | 10 | 第 0 帧 |

`a050_301000` 第 0 帧三组的网格最低都是 -61.042 mm，但同一帧左右脚底分别是 +2.2 mm 和 +14.1 mm。这一帧穿地的不是脚，是网格的其他部位，本实验不处理，也不能算到脚底修正头上。

### B 的实际效果

现有接触栈本来就把脚底反馈做到了 -1 mm 容差，所以 B 只是在这个基础上补最后 1 mm。`a050_300000` 和 `a050_300010` 的实际修正量最大 1.0 mm；`a050_301000` 在第 7–10 帧左脚用了 3.5–4.2 mm。

第 24 帧 `a050_300000` 左脚从 -0.999 mm 补到 0，膝内角从 A 的等效姿态多弯了约 0.33°。代价很小，但覆盖不全：最低点仍停在 -1 mm 的帧，是因为这些脚没有被速度阈值判为接触，B 按设计不碰摆动脚。例如 `a050_300010` 第 12 帧左脚底 -0.991 mm，接触判定为假，三组都保持原样。如果要连这 1 mm 残差也清掉，需要改的是接触判定或容差，不是髋部。

重点帧上，A 本来就不穿地：第 12 帧 `a050_300000` 左右脚底是 +2.9 / +7.1 mm，第 17 帧 +158.3 / +1.7 mm。现场看到的 -131 mm 和 -272 mm 来自缩放污染，不来自踝目标。

### C 的实际效果

补偿量只在有接触修正的帧出现：`a050_300000` 有 9 帧、最大 1.0 mm，`a050_300010` 有 5 帧、最大 1.0 mm，`a050_301000` 有 7 帧、最大 4.249 mm（第 7–10 帧）。

| 对比 | 最大值 |
| --- | --- |
| 骨盆、脊柱、头部、双手相对 B 的位移 | 等于补偿量，最大 4.249 mm |
| 踝位置 B 到 C | 0.006 mm |
| 脚底最低点 | 与 B 相同 |
| 膝角 B 到 C | 0.52° |
| 求解误差 | 0.055 mm |
| 骨长偏差 | 0.039 mm |

机制是对的：骨盆抬多少，身体就抬多少，踝和脚底不动，膝角回到接近 A 的姿态。第 24 帧 `a050_300000` 左膝 A 是 80.644°，B 变成 80.313°，C 回到 80.644°。

但量级太小。补偿量最大只有 4.249 mm，膝角变化最大 0.52°，在视觉上不构成膝盖姿态的改善，也没有改变任何一帧的穿地结论。C 相对 B 在 `a050_300000` 还多了两帧严格低于 0（31 对 29），是抬髋后小腿蒙皮的最低点越过了零线，深度仍在 1 mm 容差内。

髋部补偿的第一次实现把可达上限公式写错了（把保持 15° 膝屈曲算成了 85 mm 上限），补偿量全被压到 0；修正公式后重跑才得到上面的数。第一次的 C 结果已作废，没有写进结论。

## 判断

1. 缩放污染成立，而且是现场那份烘焙看起来严重穿地的主因。先保证烘焙从干净导入状态开始，比讨论抬谁更优先。
2. 仅修正脚底目标可以解决穿地，但现有接触栈已经做了大半。B 只补到 -1 mm 容差以内的最后一段，收益是把接触脚的残差从 -1 mm 提到 0，覆盖受接触判定限制。
3. 髋部补偿在机制上成立，不破坏踝、脚底、头部和手部（它们的位移就是补偿量本身）。但在这个动作上补偿量只有 1–4.2 mm，膝角变化不超过 0.52°，不值得为它增加独立的髋部协调逻辑。如果以后遇到脚底修正量达到几厘米的片段，再按 C 的方式锚定补偿量重新评估。

实验到此停止。正式插件仍是 1.7.5，没有把 B 或 C 合并进去。
