小腿 Roll 修正已按 `candidate_ik.diff` 合并进已安装的正式插件，版本从 1.7.5 改为 1.7.6。没有保存场景，没有提交或推送，没有改正式烘焙。开关仍默认关闭。

## 现场（实测）

合并前 Blender MCP 读到：第 1 帧，`filepath=''`，未保存，活动对象为空。这和先前提到的第 24 帧、`Bip01` 不一致，恢复目标按这次实测的第 1 帧。

## 合并了什么

正式插件目录：`%APPDATA%\Blender Foundation\Blender\5.1\scripts\addons\humanoid_retarget`

只改了两个文件：

- `ik.py`：应用审核过的差异，不是整文件覆盖。补丁后的文本与候选 `ik.py` 一致。
- `__init__.py`：仅把 `"version": (1, 7, 5)` 改为 `"version": (1, 7, 6)`。侧栏标题使用这个版本号，重载后显示「人形重定向 1.7.6」。

`retarget.py`、`motion_space.py` 和其他插件文件没有改。坐标空间入口、接触栈开关、默认 15° 膝约束、高度计划和缓存仍是正式版原有代码。

工作区 `H:\Blender_Plugin\humanoid_retarget` 的未提交修改没有动。那里的 `__init__.py` 仍是 1.7.3，和已安装的 1.7.6 不是同一份文件。

## 如何启用

默认 `_CALF_ROLL_FIX_ENABLED = False`，不烘焙时行为与 1.7.5 相同。这次没有加界面开关。

重载 1.7.6 之后，在烘焙前于 Blender 的 Python 控制台执行：

```python
import humanoid_retarget.ik as ik
ik._CALF_ROLL_FIX_ENABLED = True
```

`_CALF_ROLL_APPLY` 已经是 `restore_foot`。它只在脚 IK 打开、高度计划存在的关键帧遍里，于接触反馈之后作用于脚链，再用脚骨局部四元数保住脚的世界姿态。手 IK、FK、计划遍都不会进入这段代码。

## 合并后回归（实测）

用合并后的正式插件复制出独立测试目录 `tmp_forearm_roll\merged_official_root\humanoid_retarget`，在无界面 Blender 里重跑四个动作和四种 IK 组合。逐帧数据在 `merge_regression_frames.csv`。导入的就是这份正式插件副本，默认 Roll 开关为关。

结果与合并前的候选回归一致，没有新增 `Z<-0.01 m` 的帧。

`a050_301000` 第 0 帧两边都是 6 个顶点低于 -0.01 m、最低 -61.042 mm。这不是这次修改引入的，系统也没有达到绝对防穿地。

求解器快照里脚相对修正前最大仍是 1.8784°。播放结果的脚世界夹角不超过 0.022°。
