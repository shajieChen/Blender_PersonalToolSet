# 裙摆末端蒙皮检查

```text
裙链前3节 -> 有实际顶点权重 -> 能驱动下摆
裙链第4节 .003 -> 无权重且无子骨 -> 只见骨骼移动
```

对象为当前BlenderMCP连接的5.1.2现场角色「骨架」。用户确认问题指裙摆靠近脚踝的下摆，不是脚或鞋。以下为现场数据与临时旋转对照，不涉及Retarget源码修改。

## 已核事实

- 配置共8条裙链，每链4节。服装网格为clothing和clothing.001，Armature修改器指向「骨架」。
- 所有`.003`末骨都没有同名非零权重，且没有子骨；前3节有实际裙摆权重。
- Q_QunZi.L.002影响clothing的1256个顶点；原始顶点最低z约0.0945米。
- Q_QunZi.L.003的rest头z约0.1034米、尾z约0.0361米，尾端已延伸到服装下摆之外。

## 现场对照

对同一帧临时沿骨骼本地X轴转0.35弧度，读取evaluated mesh，逐骨恢复原matrix_basis：

| 骨骼 | 移动顶点数 | 最大网格位移 |
| --- | ---: | ---: |
| Q_QunZi.L.003 | 0 | 0米 |
| Q_QunZi.L.002 | 1256 | 0.02097698米 |

恢复后最大顶点差2.98e-8 Blender单位。没有写关键帧、改权重、删除骨骼或保存用户blend。

原始数据见skirt-weights.json；旋转对照见skirt-tip-probe.json。脚踝骨的权重检查仅用于澄清问题，见ankle-inventory.json。

## 根因与修订边界

链选择仅检查父子关系，未区分实际蒙皮骨与无权重末端定位骨。四节都模拟并绘制，使用户把不参与变形的末节误认为下摆控制段。不能通过加大刚度、碰撞或修改Retarget让无权重骨产生蒙皮作用。

推荐保留原资产权重，将链尾连续无权重且无后续蒙皮用途的定位骨移出模拟配置。骨架里的定位骨本身保留，实际最后蒙皮骨的tail作为模拟终点。若要让第4节也参与变形，则需要另行分配局部权重并检验形变，不应隐式执行。

## 实施结果

采用保留原权重的最小修订。新增`spring_bone.trim_unweighted_tips`操作器与骨骼链面板按钮，检查所选角色实际Armature修改器、顶点非零权重及变形骨，只修剪连续无权重叶端配置。保留无权重但传递至有权重子骨的中间骨；无绑定网格、全链无权重或使用骨骼封套时拒绝盲改。先计算全部修改计划，再修改链列表。

已有`humanoid_retarget.classify.skinned_bone_names`用于重定向匹配，按父级或修改器找绑定且阈值0.001；不能从独立Spring Bone导入其私有实现。本次逻辑限定为当前场景、显式有效Armature修改器、实际变形骨及叶端修剪，未新增通用蒙皮框架或跨插件依赖。

工作区版本1.0.4。三项新增业务断言先RED，最终全套67项通过。现场8条链从每条4节修正为3节；骨架仍146骨，基础/结果动作未更换，各绑定网格权重SHA-256修订前后相同。详细前后配置与哈希见skirt-chain-repair.json，可按该记录精确还原链配置。

这次修正的是模拟对象与显示对应关系，没有重新分配权重，也没有声称原网格形状因此变化。已有结果Action保留，未来重新模拟使用修正后的三节链。场景仍未由代理保存。需要用户核对当前显示的实际下摆效果后，才能关闭这项视觉验收。
