# 第31帧裙摆覆盖与穿模复核

```text
有权重并能动 -> 不等于裙边覆盖脚踝
骨尾点避开胶囊 -> 不等于最终蒙皮避开腿部
```

对象：当前BlenderMCP连接中的Blender 5.1.2、「骨架」、clothing及body。当前Action为`骨架_a050_302010.002_Spring`，基础Action为`骨架_a050_302010.002`，场景24fps、米制比例1。核对用户截图中的第31帧。

本轮仅诊断，未修改碰撞设置、权重、动作或插件源码。临时切换Action、REST/POSE和帧后，均恢复进入时的Action/slot、帧/子帧及对象和骨骼变换通道。场景未保存。

## 覆盖脚踝的缺口

| REST空间对象 | 世界Z |
| --- | ---: |
| 裙摆网格最低点 | 0.094506米 |
| 脚踝foot.L/foot.R的head | 约0.055865米 |
| Q_QunZi.L.003的tail，前次已核 | 约0.036148米 |

原始裙边最低点比脚踝高约3.86厘米。第4节骨尾比布面低，不代表它周围存在布面。蒙皮权重只分配已有顶点的变形影响，不会生成裙子或把顶点自动吸到骨尾。

模拟可通过旋转使部分裙片下垂；当前第31帧最低裙点已到Z=0.027609米，低于脚踝，但不能由这个全局最低点推出整圈裙边都盖住脚踝。当前模型没有定义裙边对各脚踝的局部覆盖目标，也没有裙片间的横向、面积或形状保持约束。

因此，原裙型偏短和局部穿插必须分别处理。若要求所有动作都盖住脚踝，需要明确整圈覆盖与长度目标；只加末骨权重或继续加大重力无法保证实现。

## 碰撞体明显小于真实腿部

现场只有大腿和小腿4个胶囊，没有脚部代理体。第31帧按对应骨骼主权重顶点、且投影落在胶囊轴段内，测量体表到轴的距离：

| 碰撞骨 | 当前半径 | 体表径向距离中位数 | 体表径向距离95分位 |
| --- | ---: | ---: | ---: |
| upper_leg.L | 3.00厘米 | 6.74厘米 | 8.05厘米 |
| upper_leg.R | 3.00厘米 | 6.36厘米 | 8.03厘米 |
| lower_leg.L | 2.20厘米 | 4.68厘米 | 5.54厘米 |
| lower_leg.R | 2.20厘米 | 5.44厘米 | 6.05厘米 |

这些采样用实际蒙皮后的顶点，不是只看骨长估算半径。当前代理体主要位于腿部内部，裙子能越过真实体表后才接近代理体。即使计入1.2厘米的骨点碰撞半径，第31帧检测到的315个交叉位置仍全部在有效代理范围之外，最大相差约3.63厘米。

脚部没有代理体也是覆盖缺口：315个交叉位置按最近身体三角形的骨骼权重归属，42个落在foot.R区域；其余分布在左右大腿和小腿。

不建议直接把所有半径统一改成最大值。应拟合各段体表和关节区域，保留裙骨固定根、长度与角限的可行空间，再重烘焙验证。

## 点碰撞没有验证最终布面

当前[`solver.py`](../../../../../../spring_bone/solver.py)第307行起只把骨尾点推出碰撞体，随后恢复骨长并施加锥限，没有骨段、蒙皮顶点、三角形或裙片间的碰撞。

[`animation.py`](../../../../../../spring_bone/animation.py)第798至816行的穿深统计同样只使用`runtime.states[index].current_tail_m`。界面中的残余穿深不是最终裙网格对身体的穿深。

第31帧只有`QunZi.R.001`尾点对扩展代理体有约0.592毫米穿入；与此同时，最终布面已经大量穿过真实腿部。其余骨点距离合格也不能证明布面合格。

还存在已核的独立胶囊端盖方向缺陷：非零端盖delta仍被强制去掉轴向分量，推出后可能留在胶囊内。该问题见前次review.md与mcp-probes.json；它需要修复，但本帧交叉位置主要在代理体覆盖之外，不能把这315个位置全归因于端盖错误。

## 基础动作与动态结果对照

在相同第31帧、相同腿部动作下，对裙摆6384个三角形与腿部1968个三角形做双向边段对三角形的实际射线交叉检测。排除端点擦碰，并按1e-5米位置合并；计数为本采样方法找到的唯一交叉位置，不是穿透深度或体积。

| 状态 | 交叉位置 |
| --- | ---: |
| REST | 0 |
| 基础动作，未动画裙骨旋转置为rest | 23 |
| 当前动态动作，原权重 | 320 |
| 当前动态动作，四节重分配权重 | 315 |

基础/动态的腿部顶点最大位置差为0；裙摆最大位置差约15.39厘米。截图也显示动态结果将左侧裙片向内收，露出腿部。现有刚度、重力和70度锥限允许这种变形，算法没有保持裙子外壳体积的条件。

权重修订让末骨可以带动顶点，但没有解决代理体与布面碰撞。320与315的计数变化不能当作外观改善或无穿模证明。

当前正在播放已烘焙的Action，碰撞不是每次播放重新计算。调整碰撞体或参数后，必须重新生成结果才能检验新的求解行为；旧Action上的`sb_penetration_m`也不能作为新权重的蒙皮碰撞结果。

## 应修订的范围与验证顺序

1. **碰撞算法**：修复胶囊端盖；复核骨长/角限投影后的残余碰撞，采用有上限、可报告失败的约束求解。用独立反例取得RED/GREEN。
2. **角色代理体**：按真实腿部体表拟合大腿、小腿及必要的脚/关节代理体，不能只根据骨长给固定半径。调整后重新烘焙，保留原Action作为对照。
3. **裙摆约束**：补足骨段及最终蒙皮/布面采样约束；必要时定义相邻裙链支撑。只修骨尾点仍不足以保证布面安全。
4. **盖踝目标**：单独决定是否调整裙型长度，以及希望在何种动作中覆盖哪些部位。不得通过隐藏腿部或任意拉伸骨长来伪装覆盖。
5. **最终检查**：相同动作下比较基础/动态和修改前后；既测尾点，也测最终网格交叉与局部覆盖，并检查实际图像。
