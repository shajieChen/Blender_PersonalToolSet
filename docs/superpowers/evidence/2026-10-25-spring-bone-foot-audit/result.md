# 裙摆穿脚量化复核与修订

日期：2026-10-25。全程未用截图评估。当前状态：用户认可数值结果；修订已应用，7项中间候选已精确清理，清理后双版本测试、真实场景及最终FBX复验通过。本次修订收尾完成，结论限定于下列对象、动作与时间采样。

## 结论和根因

问题既有实现错误，也有输入权重和使用路径问题。此前“209 点为零”只对被过滤的部分三角面及特定时间网格成立，不能作为完整裙面无穿插证明。本次纠正这一验收范围。

1. 当前实际 Action 是 `骨架_a050_302011.002`，没有 `sb_skin_contact`。上次修正的是 `302010`；旧面板却从骨架级 `result_action_name` 显示上次结果，没有核对当前 Action。这是状态显示缺陷，不能只归因于用户切换动作。
2. 生产作业与验收脚本都用“至少两个顶点权重大于 5%”筛面，漏掉身体和裙面边界。这是实现/验收同源漏检。
3. 只检查生成的采样姿势，没有检查写出 Action 后的实际帧间插值。这是实施遗漏。
4. 部分接缝没有动态权重，另一些仅约 1%–3%。骨骼移动 4 厘米时，蒙皮只跟随很少距离；零权重顶点完全不能随裙骨移动。这是原始权重与目标的冲突。
5. 第二裙面 `clothing.001` 原先未覆盖。它本次前测未发现交叉，属于已确认覆盖缺口，不冒称它就是此次穿脚根因。

## 本次修订

- `contact_bake.py`：完整选择网格面；包含同角色受动态链驱动的其他网格；身体任一顶点受碰撞部位影响即保留完整三角面。
- 候选 Action 写出后重新实际求值，步长 `min(生成步长/4, 0.0625)`；失败帧补关键帧，最多三轮，仍有交叉则恢复输入并删除候选。输出记录范围、网格、覆盖规则和复核步长。
- `panels.py`：显示实际活动 Action，旧结果或未修正动作明确提示；不会把别的片段的“0对”显示成当前状态。
- 用户已明确允许修订已证实问题的接缝。根据多轮失败面及一圈必要过渡，修改主裙面 1088/11798 个顶点的权重，其余保持；原始网格位置、裙长、Rest和八条四节链保持。低动态权重提高至归一化0.65，原非动态权重按比例缩放。备份含每个顶点的前后组权重，可精确恢复。
- 原始 Action 不覆盖，结果为 `骨架_a050_302011.002_SkirtContact`。旧结果需要重新生成，不能因保留其名称就把它当作新权重的合格结果。

## 与公开方法的关系

[VRM规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_springBone-1.0/README.md)和[VRChat官方文档](https://creators.vrchat.com/common-components/physbones/)采用骨骼半径与明确碰撞体；它们不提供任意裙面无穿插保证。不能仅加大骨尖半径就证明问题已解决。

[Bridson等的布料碰撞论文](https://www.graphics.stanford.edu/papers/cloth-sig02/)采用几何接触及考虑碰撞的细分；[IPC Toolkit](https://github.com/ipc-sim/ipc-toolkit)提供轨迹连续碰撞检测。由此作出的本项目判断是：应完整检测几何、检查帧间，并保证实际输出仍满足声明指标。本次按现有骨骼Action/FBX边界补齐，没有引入布料或CCD库，也没有宣称连续时间零穿模。
