# 骨盆与双腿协调实施档

## 目标

按用户已确认的 UE 分层方案补齐通用骨盆协调。双脚目标影响骨盆，再由现有两骨 IK 完成旋转。保持骨长、局部缩放和来源弯曲方向，不写角色名、固定补偿距离或角度。本次不移植完整 PBIK、不自动 Commit/Push。

## 修改范围

- `humanoid_retarget/foot_ik.py`：配置、纯数值骨盆位移求解、腿长约束。
- `humanoid_retarget/ik.py`：收集双脚目标、骨盆补偿、复用已有两骨求解和接地回查。
- `humanoid_retarget/__init__.py`：配置传递和面板。
- `humanoid_retarget/retarget.py`：已有 pose-channel 入口共享骨盆补偿，不增加第二套烘焙入口。
- `humanoid_retarget/motion_space.py`：如测试证实，补齐已安装版现有 world 转换合同。
- `tests/test_pelvis_ik.py`：配置、双脚、不可达、固定模式、单位与姿势回归。
- 安装版只应用相同局部补丁，保留其 Datum、脚底采样和高度计划。

## 实施步骤

1. 已读 `design_foot_ik.md` 全文、原 IK 修复计划、目标 IK 函数与设置流。原设计禁止脚到髋反馈的条款由本次用户授权明确替代；原 FK 和固定模式仍保持。探子仅一批核验配置入口与 UE BodyMover/PBIK，返回后不重复全仓检索。
2. UE 参考：`IKRigBodyMoverSolver.cpp:17-83`、`PBIKSolver.cpp:281-297,367-422,514-605`、`PBIKConstraint.cpp:28-65,111-196,309-328`。预补偿采用目标质心减输入质心；旋转保持默认关闭。约束迭代参考 PBIK 的位置校正，双骨长继续由已有解析求解保证。
3. 首批真实双腿骨架 RED selected=6、4 failed；初步 GREEN selected=10。补充骨盆倾斜用例取得 RED selected=11、1 failed。配置：PRE_PULL、PIN_INPUT、FREE，位移总权重、水平/垂直权重、迭代次数、来源伸展保持权重、骨盆姿态调整权重。来源姿势保持是插件的自适应策略，不冒充 UE PreferredAngles 的等价移植。
4. 纯计算用米制 motion space；骨盆位移与旋转写入 armature-local pose。每条腿的可达区间先由目标骨长限定，再按来源链伸展保持权重收缩。所有双脚约束共同修正一个骨盆变换，冲突保留残差，不改变骨长。来源腿根处于脚上方时，约束不额外把腿根压到脚下；踢腿的负高度由来源方向连续放行。
5. 补偿后重新求解已有脚目标并复核接触。Planting 每帧只推进一次，接触高度计划每帧只应用一次。手目标在骨盆移动后重解；pose-channel 仍保留其关节限位最终写入权。
6. 修改后检查完整局部 diff、实际 bpy API、坐标转换、无新增注释、字节编码与换行；然后运行 Blender 5.1 聚焦和相关回归。C++ 只读，不构建 UE。
7. 当前场景保存副本，先跑单帧16，再完整53帧；另跑不同骨长、对象统一缩放和多个来源动作。确认动作集合，避免再次误烘焙 NLA 的全部动作。
8. 保存必要证据 → 用户核对预览 → 清理本次临时诊断 → 清理后复验 → 最终报告。尚待核对时只报告 Preview，不宣告完成。

## 强制约束

- `__init__ -> retarget/ik -> foot_ik/mathutils` 单向依赖。所有 bpy 写入在 Blender 主线程。
- 本帧数据为局部变量，无新增全局状态、handler、timer、日志或后台服务。已有接触诊断不属于本次清理范围。
- 单次作业拥有几何与 Action 状态；不删除用户动作、修改 rest、骨名、层级或缩放继承。失败沿已有烘焙回滚。
- 先最小双腿用例，再扩展回归；只在真实缺口出现时增加探子批次。
- 三个变化检查：不同骨长由参考链比例适配；对象变换由 MotionSpace 处理；固定骨盆或零权重走原行为。多脚/坡面/完整刚体旋转不提前实现。
- C/C++ 编码、namespace、MemLabel、unique_ptr、ABI 门均 NotApplicable；本次没有 C/C++ 修改。

## 验收标准

- `blender.exe --background --factory-startup --python-exit-code 1 --python tests/run_pose_channel_tests.py -- test_pelvis_ik.py`：selected>0、RED 可归因、GREEN 退出0。
- `test_ik_pose.py`、`test_ik_pole.py`、`test_limb_fold.py`、`test_pelvis_height.py`、pose-channel 与 joint-limit 相关测试回归；原工作区已知 UI 默认差异单列。
- 固定和零权重不移动骨盆；预补偿等于 UE 质心公式；双腿约束共同生效；不拉长骨骼、不积累局部缩放或轴向扭转；无来源动画的可达姿势不引入位移。
- 真实动作记录骨长误差、脚底高度、膝角、补偿位移、连续性和重复一致性。数值/Runtime/Visual 独立报告。
- 现场提供新 Action 预览，原动作保留。用户未确认、临时诊断未清理或必要复验未通过时不报告最终完成。
- 临时内容清单：后台进程内采样/拦截、单帧与多帧输出、对比预览。后台进程自然退出；拦截在 finally 恢复；临时执行脚本清理；正式测试、备份和证据保留。
- 源码对应边界：UE `FRigidBody::ApplyPushToRotateBody` 使用偏移与推力叉积产生角修正，`ApplyRotationDelta` 限制每轮角增量。插件采用同类位置约束梯度、旋转力臂和30度单轮上限，继续使用现有两骨解析求解。它不是 UE 刚体质量/关节求解器的逐行移植。来源腿方向生成的期望腿根及双点姿态拟合属于本插件自适应策略，权重0可关闭。
- 初步仅平移的真实53帧预览把左膝165度改善到138度，但右膝接近伸直，故不验收该版。加入双向伸展区间与骨盆旋转响应，避免把冲突转移到另一条腿。
- 效率复盘：首轮真实动作采样误把 `bake_retarget` 返回的 Action 当作三元组；保留失败日志，核对 `_frame_range` 后修正采样代码。未改业务实现、未把该次失败计为Runtime通过。

## 禁止事项
