实际映射及链末端：

```text
source: Pelvis -> Spine
target: Bip01 Pelvis -> Bip01 Spine
```

`B_s/B_t` 是 `_body_matrix` 的 left/up/forward 列向量。身体轴只读 rest `head_local`；不随当前骨盆旋转更新。`R_pose` 来自 `pose_bone.matrix`，已含父骨旋转；`R_rest` 来自 `bone.matrix_local`。`D = R_pose @ R_rest.inverted()`。

将 rest 身体 left `l` 经 D 旋转后投影到身体 up `u` 的垂直平面，yaw 为 `atan2(u dot (l cross v), l dot v)`。`lost yaw = wrap(source yaw - target yaw)`。不读 pelvis 的单个 Euler 通道。

髋链倾角是 hips→spine 与各自身体 up 的夹角；倾角误差是两夹角之差的绝对值。另列身体坐标下的完整髋链方向夹角，避免把倾角相同误称为方向相同。

## 为什么绝对轴复制不安全

在各自身体坐标中比较两侧 rest pelvis 旋转，本轮差角为 `90.015684619°`。局部骨轴不是共同的身体轴；父骨层级也参与 pose 旋转。

直接复制来源 `matrix_basis` 会把来源的父相对轴含义当成目标轴含义。直接复制 `matrix_local` 或姿势绝对朝向，会把来源 bind 的约 90° 轴差带入目标。现有算法用链方向求 swing、保留目标 bind roll；单个角的 transfer 可以单独实验，不能因绝对轴复制不安全就预先否定它。

本轮 A/B 均把五帧 yaw 残差降至 1° 内，推翻了“一个角不能恢复这对骨架偏航”的强断言。但这两种办法均需要改变非髋局部四元数，因此没有推翻本任务的 DO_NOT_PATCH 决策。详见唯一实施指令文档。

这些世界 dot 已在基线超过 `1.5e-7`。身体坐标下对应 dot 的最大误差仅 `3.519406988e-13`。二者不能混用；本轮 A/B 的正式硬门仍采用原始世界 dot。

双手 quaternion 都是 `(1,0,0,0)`，但原始 FBX 导入后的微小 scale 使 `matrix_basis` 不满足严格 identity 门：五帧 hand_l 的最大元素误差均为 `1.192092896e-7`，hand_r 均为 `2.384185791e-7`。左手三个 scale 分量约为 `1.000000119209`；右手约为 `(1.000000119209,1.000000238419,1.000000238419)`。未归一化或清零 scale 来掩盖失败。

这两项是当前导入基线的独立限制。即使将它们排除，A/B 的非髋四元数门仍会失败。
