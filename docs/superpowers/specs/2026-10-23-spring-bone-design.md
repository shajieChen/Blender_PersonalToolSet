# 动态骨骼插件设计

```text
Blender_PersonalToolSet
+ humanoid_retarget -> 人形动作重定向
+ spring_bone       -> 裙摆、头发、饰物的骨骼二次运动

已有动作 -> 固定步采样 -> 尾点模拟与碰撞 -> 生成预览 -> 新 Action
```

日期：2026-10-23。状态：设计待实施。本次只交付文档。

推荐新增独立插件 `spring_bone`，与 `humanoid_retarget` 位于同一目录层级，独立安装、启用和注销。首版针对已有骨骼和权重的裙摆，也适用于发束、尾巴和吊饰。Retarget 完成后，用户在目标骨架上选择其输出 Action，再运行动态骨骼。两者之间只传递 Blender 原生骨架和 Action，不互相导入 Python 模块。

### 首版包含

- 手工选择连续骨骼生成一条链，多次添加形成整圈裙摆；允许多个互不重叠的链。
- 每链刚度、拖曳、重力、碰撞半径和混合权重；首版统一链参数，不增加逐关节曲线编辑器。
- 外部球、胶囊碰撞体，绑定到同一骨架中的非模拟骨骼，如左右大腿、小腿和骨盆。
- 可选锥形角度限制；固定步求解、预热、生成预览、停止预览、烘焙为新 Action。
- 保存配置到 blend；预览和烘焙使用同一数值路径。

### 首版排除

自动绑裙骨、自动权重、网格布料、裙片之间的弹簧、链间碰撞、网格或骨段连续碰撞、布料自碰撞、实时修改参数即模拟、VRM 导入导出和 VRM 一致性认证均不在首版。多链只能带动已有权重，无法保持布料面积或防止相邻裙片分开。

首版不承诺消除所有裙摆穿模。尾点球与腿部代理体的离散碰撞，不能证明骨段中部、三角面或高速跨越时不穿透。

## 2 职责与依赖

```text
spring_bone/__init__.py -> properties.py
          |            -> operators.py -> animation.py -> solver.py
          +------------> panels.py          |
                                         mathutils
```

| 拟新增文件 | 唯一职责 |
| --- | --- |
| `spring_bone/__init__.py` | add-on 信息、类注册顺序、文件加载和注销清理 |
| `spring_bone/properties.py` | 骨架配置、链列表、碰撞组与字段校验入口 |
| `spring_bone/panels.py` | 动态骨骼面板，显示预检错误、操作和进度 |
| `spring_bone/operators.py` | 添加链、代理体编辑、预览与烘焙操作；持有 modal TIMER |
| `spring_bone/animation.py` | `SpringBoneBakeJob`、输入采样、姿势转换、Action 写入及恢复 |
| `spring_bone/solver.py` | `SpringChainState`、固定步、长度、球/胶囊与锥限制；只依赖 mathutils 和标准数学库 |

先使用具体数据类、少量函数和一个作业类。链、碰撞体是当前业务数据，不引入通用物理世界、插件注册表或抽象求解器。参数与状态分离；数值模块不得导入 bpy、UI 或 Retarget。

## 3 配置与资源

配置使用骨架 Object 上的 `sb_settings`，避免共享 Armature data 的不同对象串配置。存储 `schema_version=1`、链名称、骨骼名列表、参数、碰撞组和绑定骨名。名称只用于查找；每次作业重新校验对象与骨骼，不保存跨作业 RNA 指针或模拟缓存。骨骼重命名或删除后提示重新绑定，不能静默匹配其他骨骼。

| 字段 | 首版默认与约束 |
| --- | --- |
| `stiffness` | 1.0，有限且>=0；沿每步基础方向的恢复系数 |
| `drag_force` | 0.5，范围0到1；每固定步缩放惯性位移 |
| `gravity_power`、`gravity_dir` | 0.0、(0,0,-1)；强度>=0，方向归一化，零方向且强度>0时报错 |
| `hit_radius_m` | 0.01米，有限且>=0；骨尾代理球，不代表裙片厚度 |
| `weight` | 1.0，范围0到1；链最终旋转混合 |
| `cone_enabled`、`cone_angle_deg` | False、60度；开启时范围0到180度 |
| `inertia_space` | WORLD；可选FOLLOW_TRANSLATION，后者必须指定合法祖先 |
| `warmup_seconds` | 0.5，范围0到5秒，换算为整数60Hz步数 |
| 碰撞体 | 手工设置形状、非模拟绑定骨、局部偏移/轴端和米制半径；不自动生成身体尺寸 |

这些是初始编辑值，不是已验证的通用裙摆预设。每次启动将可编辑字段复制为作业快照，逐项检查有限数和合法范围。

| 数据 | 拥有者 | 生命周期 |
| --- | --- | --- |
| 原骨架、网格、输入 Action | 用户 | 作业只借用，不删除、不修改输入曲线 |
| 配置和代理体定义 | 骨架 Object | 随 blend 保存；卸载插件不删除用户配置和代理物体 |
| 碰撞显示 Empty | 用户确认添加的代理体 | Object 引用明确记录；运行时只读其形状参数和骨骼局部偏移，不读取依赖模拟结果的变换 |
| 数值快照、两帧尾点和输出旋转 | `SpringBoneBakeJob` | 一次作业内；成功或取消后释放 |
| 未完成结果 Action | 作业 | 创建后立即登记；失败精确删除 |
| 预览 Action 和入口快照 | 预览会话 | 停止、重新生成、Undo、文件加载或注销时成对释放 |
| 正式结果 Action | 用户 | 成功提交后保留 fake user，可独立播放和导出 |

所有 bpy 读取、采样、姿势修改和 Action 写入均在主线程。modal 只在完整采样点或完整求解步之后让出，不使用 Python 后台线程调用 bpy。依据为 [Blender 5.2.1 线程限制](https://raw.githubusercontent.com/blender/blender/v5.2.1/doc/python_api/rst/info_gotchas_threading.rst)。

## 4 使用流程与姿势所有权

1. 完成绑定和基础动画。Retarget 用户先停止重定向操作，选中最终目标骨架及目标 Action。
2. 在姿态模式选中裙摆的一条根到末端连续链，点击添加链。分支、断链和重复占用给出明确错误。每根骨骼以自身 tail 为模拟点，末骨也有真实长度，不要求额外末端骨。
3. 添加骨盆球及左右腿胶囊，调整偏移、半径和胶囊两端。代理体不自动猜测腿部名称，不修改腿骨或权重。
4. 设置范围、参数和预热，点击生成预览。主线程分时采样及求解，完成后临时切到预览 Action；正常播放由 Blender 原生动画完成。
5. 停止预览恢复输入 Action；调整参数后重新生成。点击烘焙新动作时，直接提升未过期的预览结果，或用同一作业重新计算。不得以预览 Action 作为下一次模拟输入。
6. 结果写为独立 Action，例如 `Walk_Spring`。保留基础动画的非模拟通道，只替换配置链的旋转通道；结果为完整动作，不是需要额外叠加的增量层。

首版预览不注册 `frame_change` 或 depsgraph 姿势写回 handler。生成期间独占场景采样与目标写入；完成后也不持续施加动力学。这样拖动时间轴、倒放和渲染直接读取生成结果，不从上一播放帧继续积分。

作业开始前拒绝已在播放、NLA tweak mode、输入 NLA 已开启、多对象共用待写 Action slot、不可编辑链接数据和其他活动 modal 编辑。插件内禁止第二次作业，modal 拦截编辑与 Retarget 快捷操作，面板禁用输入。暂停预览期间也不允许重定向写同一骨架；开始重定向前先停止预览。外部脚本并发写入不在支持范围；检测到 Action、骨架或配置身份变化即取消，不能声称身份检查能发现所有原地修改。

## 5 坐标与公式

公式唯一依据为 [Spring Bone 公式证据](../plans/2026-10-23-spring-bone-formula-evidence.md) 第 3、4、6、7 节。采用其已核 VRM 风格递推和外球/胶囊投影，独立实现数值函数，不搬运 UE 源码，不将 UE 刚度或阻尼参数混入本算法。以下策略是本插件设计，不声明与外部实现逐输入等价。

### 世界空间与骨长

所有尾点、head、代理体和重力在世界空间米制下求解。`meters = world_blender_units * scene.unit_settings.scale_length`，参数半径以米保存；场景单位比例必须有限且大于零。场景单位或骨架 rest 改变即使作业失效。

首版只支持固定的正统一对象缩放、无 shear、无镜像，以及链骨无动画缩放、无动画平移、标准继承旋转和 FULL scale 继承。动态骨的约束、驱动器、B-Bone 形变和特殊继承模式预检拒绝；非模拟祖先上的动画/IK可作为采样后的基础姿势输入。零长骨、循环引用、动态链作为碰撞绑定祖先均拒绝。

输入必须具有有效单Action，Action混合为REPLACE、影响值为1；非模拟祖先或碰撞体的约束/驱动若间接依赖模拟链，同样拒绝，不能仅检查直接父子关系。首版支持QUATERNION和六种Euler旋转模式，AXIS_ANGLE及旋转模式动画预检拒绝。

在起始基础姿势采样各段长度并冻结；后续采样发现长度偏离容差即失败，不逐帧悄悄改长度。骨骼按父到子求解，下段 head 使用已求解父段的 tail；首段 head 来自基础动画。

令采样姿势矩阵为 `B_i`、已求解父姿势为 `S_p`。内部骨的参考姿势为 `S_p * inverse(B_p) * B_i`，首骨使用基础动画及非模拟父姿势。它决定 head、参考方向和原始 twist，避免把子段固定在未经模拟的父坐标上。

### 一步求解

```text
inertia = (currentTail - previousTail) * (1 - dragForce)
stiffness = referenceDirection * fixedDt * stiffness
external = normalize(gravityDir) * fixedDt * gravityPower
candidate = currentTail + inertia + stiffness + external
tail = head + normalize(candidate - head) * length
tail = cone_limit(tail)
对按配置顺序排列的碰撞体：推开 -> 恢复骨长 -> cone_limit
previousTail = currentTail
currentTail = tail
```

上式保持原证据的 `dt` 一次项，不改为 `dt²`；`stiffness` 和 `gravityPower` 是此离散模型的系数，不标成 N/m 或 m/s²。碰撞距离为负才推出：球为 `|tail-center|-radius-hitRadius`；胶囊先求轴段最近点，再用球距离式。退化胶囊按球处理。

每步默认执行一次有序投影；多个体或角限冲突时可能仍有穿深，记录最大残余穿深并供用户检查，不能无限迭代或偷偷改变骨长。锥轴为该步参考姿势的骨骼 +Y，范围为 0 到 180 度。

近零方向使用上一有效方向，再回退基础方向；球心/胶囊轴上的碰撞方向按上一有效径向、参考方向的垂直分量、固定轴顺序确定。反平行旋转选择与基础骨轴垂直的确定性轴。所有 epsilon 命名、按米或无量纲区分。这些是本插件退化规则，必须有独立测试，不能标成外部源码等价。

旋转为参考世界旋转左乘最短弧 swing，保留基础 twist；再按父到子转换为本地 basis。使用 `Bone.convert_local_to_pose(..., invert=True)` 及明确父/rest矩阵，不把世界四元数直接写入 `rotation_quaternion`。仅写模拟骨旋转；输入 location、scale 和其他骨骼通道不改。

混合采用基础旋转与动态旋转的最短弧 slerp，`weight=0` 完整旁路，`weight=1` 全模拟；子段继续使用混合后的父姿势。碰撞按模拟目标计算，混合后可能重新穿入，验收须检查最终姿势和实际网格。

### 参考平移

默认 `WORLD` 保留整体平移产生的惯性。可选 `FOLLOW_TRANSLATION` 指定链首非模拟祖先，在每步先将其平移差同时加到两帧尾点；重力仍是世界方向。不跟随参考旋转，不称为完整 VRM center space。首次采样、重新生成和输入不连续时重新初始化尾点，不能继承上次运行状态。

## 6 时间与动画数据

固定模拟频率为 60 Hz，`fixedDt=1/60`，用整数 tick 计算时间，不累计浮点帧号。场景帧映射为 `frame = start + seconds * fps / fps_base`，支持 24、30、60 和分数帧率；展示帧率不改变积分次数。重力、刚度、拖曳不随输出帧率重新解释。

预热默认 0.5 秒，保持起始基础姿势运行 30 步，不向输出写预热帧。输出在每个 60 Hz tick 插入旋转关键帧，允许子帧；范围末端不在网格时，额外采样一个固定步用于端点插值，输入时间夹到结束帧。端点输出不改变已有固定步状态。四元数相邻键做半球连续，使用 LINEAR 插值。渲染采样时刻不保证满足离散碰撞，必须单独检查。

作业分为采样、模拟、写入、提交四阶段。采样前保存原始 basis；每个时间点先恢复基础输入及未动画通道，再 `frame_set` 求值并复制矩阵。采样阶段绝不写模拟姿势，避免上一帧结果被当成新输入。数值阶段只读快照；写入阶段在输入 Action 的独立副本上改模拟通道。

Action 单独使用所选骨架对应 slot；输入含多个 slot 或复杂多层 Action 时首版拒绝，不删除其他对象的数据。仅在结果副本中删除模拟骨原旋转路径，并按骨骼原rotation_mode写入：QUATERNION写四元数，Euler以兼容上一输出角的转换保持连续。内部始终用四元数求解，不更改骨骼rotation_mode，保证切回基础Action仍能播放。最终插值姿势须覆盖Euler接近万向锁的样本。

非模拟曲线及模拟骨 location/scale、输入 Action、原 NLA和driver配置保持原状。结果只保证所选范围，范围外模拟骨姿势不作为交付；设置预览时间轴为该范围，并在结果属性记录范围，不能以复制后Action的全曲线范围代替。默认不加入 NLA，也不写 `hr_actions`；用户通过原生 Action 选择器选结果。

预览复用只在同一会话、配置与输入未变时允许。检测到 Undo、骨架编辑、Action编辑、帧率或单位改变即失效；首版无法可靠确认未变时重新采样，不构建跨会话缓存。

## 7 失败与生命周期

`SpringBoneBakeJob` 保存入口 Action/slot、AnimData存在性、NLA开关、受影响骨 rotation_mode/basis、帧/子帧/范围、选择和活动对象，以及本次创建 Action 身份。操作器保存窗口 TIMER 与进度；停止与清理均可重复调用。

取消或异常：先停止调度，恢复入口动画与姿态，再仅删除本作业未交付 Action，结束进度并释放数值数据。成功：完成结果和检查，再一次性切换结果Action并移交所有权。不得用返回 CANCELLED 代替恢复。

预览挂接后保留入口快照；停止预览恢复它并删除本会话预览Action。烘焙提交后结果归用户，不被注销删除。`load_pre`、`undo_pre` 和注销在移除属性前停止活动会话，加载后不自动启动模拟。用户中途切换 Action 时不再盲目覆盖新选择；停止旧会话并提示已失效，只清理自己仍拥有的资源。

生成与正式烘焙分别作为一次可撤销操作，前台验证一次 Ctrl+Z 的实际效果。只保留插件会话的单个活动作业引用，不创建通用全局缓存或跨插件锁；所有入口检查活动状态，场景/窗口改变或目标失效进入取消。

## 8 取舍与后续变化

| 选择 | 收益 | 代价和未选原因 |
| --- | --- | --- |
| 同级独立 add-on | 无Retarget依赖，可处理手工或导入动作 | 多一次用户选择Action；嵌入Retarget会耦合绑定与烘焙职责 |
| VRM风格尾点链 | 与旋转骨骼、骨长和腿部代理体匹配 | 参数为离散系数；UE SpringBone递推和输出量不同，不混用 |
| 生成预览后播放 | 单一姿势写入者，跳帧和倒放稳定 | 改参数需重新生成；实时handler增加求值反馈和生命周期风险 |
| 独立Action副本 | 原动作可回退，输出可单独导出 | 结果体积增加；直接覆盖原动作和隐式NLA叠加不利于恢复 |

三项后续变化只验证边界，不提前实现：增加风场只改变每步外力输入；增加内部碰撞形状只扩展数值碰撞和字段校验；增加批量片段由调度层逐Action新建作业。三者不要求改Retarget、公共基类或引入求解器注册系统。实时预览如后续确需支持，须独立设计无反馈的输入求值边界。

## 9 验证与完成边界

## 10 2026-10-24 裙面与 FBX 修订

本节记录后续用户要求：保留原静态裙长和四节模拟，修复穿模，结果必须随 FBX 骨骼动画导出。当前场景 Blender 5.1.2 与后台 5.2.1 均已实测，最低版本声明同步为 5.1.2。原 Spring 尾点求解保持原边界，另加可选的裙面后处理；这不是把尾点碰撞宣称为布料。

依赖为 `operators → contact_bake → skin_collision`，同时复用 `animation` 的 Action/Slot 与四元数处理。数值模块只使用 NumPy/mathutils，无 bpy；所有采样与写入在主线程，以可取消小工作单元运行。没有与 Retarget 的 Python 导入依赖。

真实裙面和身体网格使用同一骨架的线性顶点组蒙皮。身体碰撞范围来自代理体绑定骨及其后代。先检测三角形相交，再在现有自由度内寻找修正：保留原旋转优先，允许有上限的链首三维位移及模拟骨旋转。输出只新增 Action；不改 Rest、骨长、裙长、网格或权重。

相对于初版的明确扩展：初版仅写模拟骨旋转；裙面后处理还写链首 location。初版复制非模拟曲线的数值；后处理遇到反号四元数时，只在结果副本内翻转等价旋转键并修复跨半球插值，保留关键帧旋转姿势，原 Action 不动。修正数量和路径写入结果元数据。这两项只属于新增后处理，不能反推初版物理求解已经支持网格碰撞。

Retarget 仅有两处必要修订：未来烘焙写键时保持相邻四元数同半球；普通 FBX 入口读取通用 `fbx_sample_step` 动作元数据。默认步长仍为 1，既有映射、IK、片段选择和绑定流程保持原职责。A-Pose 重烘焙的密集子帧支持不在本次完成声明内。

工作 Action 和未交付结果由 `SkirtContactBakeJob` 拥有，取消/失败/卸载对称清理；结果通过原生蒙皮检查才移交。用户改变 Action、Slot、模式或数据后，不覆盖其新选择。只有一个既有插件会话调度作业。

验证以实际网格为准：求解预测误差 <=1e-5 米；声明的采样点三角形交叉为 0；FBX 回导按片段相对时间比较。相切共面、完全包围体、任意连续时间和布料自碰撞不由当前表面交叉检测保证。单帧成功、点碰撞通过和有限数均不能替代整段裙面验收。

实施及执行效率、诊断清理约束见 [裙面修订实施档](../plans/2026-10-24-spring-bone-skin-contact.md)。
